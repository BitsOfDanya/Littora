# Littora

Littora — веб-сервис спутникового мониторинга плавающего макромусора для специалиста по экологическому мониторингу морских акваторий. Специалист выбирает район и дату; сервис находит снимок Sentinel-2 L2A и показывает его качество (облака, тени, пропуски, доля воды по маске SCL), запускает детектор и выводит на карту вероятность, зоны вероятных скоплений и маски, даёт концентрацию в шт./км² с интервалом и статусом, сопоставляет зоны с измерениями с судна из датасета кейса и выгружает результат в GeoJSON и CSV. Проект команды «5 bit» для КосмоХакатона 2026, кейс «Детектирование и оценка концентрации макропластика в морских акваториях».

Основные функции:

- каталог снимков Sentinel-2 L2A по району и периоду с оценкой пригодности: облачность, покрытие района, риск блика по высоте Солнца;
- детектор RA-U-Net (ONNX, 11 каналов): калиброванная вероятность, зоны от 2 связных пикселей в маске моря, флаги «вероятно судно», «рядом сооружение», «порт», «неустойчива к поворотам»;
- слои снимка: RGB, ложные цвета B08-B04-B03, FDI, NDVI, маска качества, доля покрытия пикселя; значения пикселя под курсором и линейка;
- концентрация в шт./км² по полевым профилям с 80 % конформным интервалом — только в области и сезоне полевых данных, со статусом «исследовательская оценка»; иначе «концентрация недоступна»; по снимку концентрация не выводится;
- полевые измерения кейса на карте и сравнение зоны с ближайшими измерениями с судна;
- сценарий дрейфа зон на 72 ч вперёд и 48 ч назад, риск выноса на берег, возможные источники;
- ряд детекций по пролётам и сравнение двух дат; план обследования: маршрут судна, вылеты БПЛА, GPX;
- проверка зон командой с выгрузкой отметок; отчёт оценки моделей с печатной версией.

## Быстрый старт

Нужен Docker с Compose v2. Ключи API и токены не нужны: каталог снимков Earth Search STAC, Open-Meteo и OpenStreetMap Overpass открыты. В `.env.example` только необязательные настройки (уровень логов, CORS, порты, демо-режим), поэтому копировать его необязательно.

```bash
cp .env.example .env
```

```bash
docker compose up --build
```

- http://localhost:3000 — приложение;
- http://localhost:8000/api/docs — документация API (OpenAPI).

Ресурсы:

| Ресурс | Сколько |
|---|---|
| Диск | образы ≈1,3 ГБ (backend 0,8 ГБ, frontend 0,4 ГБ), с кэшем сборки — с запасом ≈3 ГБ; результаты анализов — в томе `analyses`, ≈3 МБ на анализ |
| Память | ≈4 ГБ для Docker: на районе предельного размера (12 млн пикселей) массив 11 каналов float32 занимает ≈0,5 ГБ, скользящее окно держит его копию |
| Процессор | только CPU; GPU сервису не нужен |
| Сеть | доступ к Earth Search (снимки), Open-Meteo (условия съёмки, дрейф), Overpass (сооружения) |

Фронтенд собирается с `NEXT_PUBLIC_API_BASE_URL=/` и проксирует `/api/*` в сервис `backend`, поэтому CORS настраивать не нужно; он стартует после того, как backend прошёл проверку здоровья. Backend монтирует только на чтение `data/case`, `data/aoi`, `data/validation`, `reports`, `models/detector/service` и `models/concentration/service`; результаты анализов, кэш Open-Meteo, кэш OpenStreetMap и отметки команды хранит в томе `analyses` (`/storage`).

### Демонстрационный стенд

Развёрнутая версия: `http://5.129.225.86/`. Push в `main` запускает workflow `.github/workflows/deploy.yml`: он проверяет backend и frontend, передаёт архив коммита на сервер и вызывает `deploy/deploy.sh`. Скрипт под блокировкой собирает образы, обновляет Compose, ждёт healthcheck обоих сервисов и проверяет главную страницу и `/api/v1/health`; номер развёрнутого коммита записывается в `/opt/littora/deployed-revision`. Backend на сервере слушает только `127.0.0.1:8000`, настройки — в `/opt/littora/shared/.env`, результаты анализов — в Docker volume. Ключ SSH для деплоя хранится в секретах GitHub Actions, в репозиторий не попадает.

### Первый анализ

Команды — во втором терминале (или запустите Compose с `-d`). Пример — Новороссийск, Цемесская бухта, 4 сентября 2025 г., район ≈11×9 км, целевая величина «весь плавающий мусор» (`litter-visual`):

```bash
curl -s -X POST http://localhost:8000/api/v1/analyses -H 'Content-Type: application/json' -d '{"aoi_id":"novorossiysk","aoi_name":"Новороссийск","bbox":[37.76,44.66,37.9,44.74],"date":"2025-09-04","window_days":1,"scene_id":null,"target":"litter-visual"}'
```

Сервер ждёт результат до 20 с. Если расчёт не закончился, ответ — `202` с `"state": "running"` и `id`; та же команда, повторённая позже, вернёт готовый результат. Полный расчёт этого района занимает ≈37 с (раздел «Инференс и производительность»), повторный запрос возвращается сразу из сохранённого результата.

Что должно получиться: снимок `S2B_T37TDK_20250904T083254_L2A` (08:37 UTC), снимок пригоден; детекция «обнаружено» — в нашем прогоне 30 зон, у 22 из них есть флаги («рядом сооружение» 13, «вероятно судно» 12, «порт» 6, «неустойчива к поворотам» 6; флаги у одной зоны могут совпадать); концентрация «концентрация недоступна»: район вне области полевых профилей величины `litter-visual` (S3 — Северное море, S4 — рейс DOORS в Чёрном море, до 60 км от точек учёта).

Идентификатор анализа есть в ответе и в истории запросов:

```bash
curl -s "http://localhost:8000/api/v1/analyses?aoi_id=novorossiysk"
```

Выгрузка, где `<id>` — поле `id` из ответа:

```bash
curl -s -o novorossiysk.geojson http://localhost:8000/api/v1/analyses/<id>/export.geojson
```

```bash
curl -s -o novorossiysk.csv http://localhost:8000/api/v1/analyses/<id>/export.csv
```

В интерфейсе то же самое: http://localhost:3000 → «Открыть рабочее пространство» (или `Enter`) → район «Новороссийск» → дата → «Запустить анализ». Внизу слева должно быть «API в сети». Клавиша `?` показывает все горячие клавиши.

```bash
docker compose ps
```

```bash
docker compose down
```

### Локальный запуск без Docker

Нужны Python 3.11 или новее (в Docker — 3.12) и Node.js 22.12 или новее (в Docker — 24).

Backend, из корня репозитория:

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

```bash
cd backend && .venv/bin/uvicorn app.main:create_app --factory --reload --port 8000
```

Frontend, во втором терминале:

```bash
cd frontend && npm install
```

```bash
cd frontend && npm run dev
```

Без `.env` фронтенд обращается к `http://localhost:8000`, backend разрешает CORS для `http://localhost:3000`. По умолчанию открыт участок «Разрезы T1–T2» в Чёрном море с выбранным снимком дня учёта.

## Целевая величина (O1)

Задана в `backend/config/case.toml`. Единица — шт./км², C = N / A.

**Основная величина — `plastic-visual`: концентрация плавающего пластика, визуальный учёт с судна, предметы от 2 см** (профиль `S2_visual_GT2`, Саргассово море, апрель 2015). Это именно пластик, а не весь мусор; число предметов и авторская площадь известны, поэтому C = N/A проверяется по каждой записи (63 из 63 совпадают). Спутниковых пар у этого профиля нет: съёмка раньше запуска Sentinel-2.

| Ключ | Что считаем | Профили | Событий | Роль |
|---|---|---|---|---|
| `plastic-visual` | суммарный пластик ≥ 2 см, визуальный учёт | `S2_visual_GT2` | 63 | основная |
| `plastic-trawl` | макропластик 5–50 см, поверхностный трал | `S1_trawl_5_to_50` | 83 | второй профиль пластика |
| `litter-visual` | весь плавающий мусор ≥ 2–2,5 см, визуальный учёт | `S3_visual_GT2`, `S4_visual_GT2_5` | 74 | Чёрное море: пары со снимками |

Профили с разными методами и размерными классами не смешиваются, метрики считаются по каждому отдельно. Весь мусор не выдаётся за пластик: долю пластика из публикаций к отдельным наблюдениям не применяем. В районах кейса в Чёрном море интерфейс по умолчанию запрашивает `litter-visual`, потому что там измерен весь мусор; API без параметра `target` использует основную величину.

### Правила подбора пар

Все пороги — в `[pairing]` файла `backend/config/case.toml`:

| Параметр | Значение |
|---|---|
| каталог, коллекции | Earth Search; `sentinel-2-c1-l2a`, пропуски архива — `sentinel-2-l2a`; Landsat — `landsat-c2-l2` |
| окно поиска | ±3 сут от даты события |
| сдвиг по времени | не больше 12 ч |
| облачность тайла | до 40 % |
| след события | полоса учёта; точка без полосы — круг `unknown_extent_buffer_m` = 6 км |
| доли SCL в следе | пропусков до 5 %, облаков и теней до 10 %, воды от 50 %, «яркой воды» (NIR ≥ 0,04) до 30 % |
| скорость дрейфа для оценки смещения | 0,2 м/с (`drift_km_max` в `pairs.csv`) |

Маска качества одна для реестра и сервиса (`backend/app/earth/raster.py`): вода — SCL 6; облака — 8, 9, 10; тени — 3; снег — 11; суша — 4, 5; нет данных — 0, 1; прочее — 2, 7; «яркая вода» — вода с отражением NIR выше 0,04 (блик, пена, взвесь).

Порядок: событие → геометрия следа → дата и время → поиск сцен → покрытие следа → сдвиг по времени → облачность тайла → доли SCL в следе → решение. Значения в таблицах округляются в сторону отказа, поэтому отвергнутая строка никогда не выглядит проходящей.

Если время учёта неизвестно (S4), сдвиг ограничивается светлым временем суток в точке учёта: визуальный учёт ведут днём, поэтому для снимка того же дня сдвиг не больше расстояния до восхода или заката (для принятых пар — 8,46–8,63 ч); в полярный день граница — сутки UTC; иначе причина `sync_uncertain`. Соседние тайлы одного пролёта помечаются как дубли, статистика считается по пролётам. У Landsat C2 L2 лучшее возможное решение — `candidate`: его маски качества без ключей не читаются.

Решения: `accepted`, `candidate`, `rejected`, `not_evaluated` (ошибка каталога или чтения), `not_used` (событие без целевой величины). Причины: `before_mission`, `not_acquired`, `no_scene_in_window`, `time_shift`, `sync_uncertain`, `partial_coverage`, `tile_cloud`, `quality_unverified`, `nodata`, `footprint_cloud`, `no_water`, `bright_water`, `no_date`, `no_position`, `read_error`, `catalog_error`, `no_target`.

## Детектор (T2)

### Данные и разбиение

- MARIDA: 1 381 патч 256×256 из 63 сцен, 11 каналов B01–B12 без B09 и B10, 15 классов с уверенностью разметчика 1–3. Разметка сделана на L1C после ACOLITE.
- Разметка перенесена на снимки `sentinel-2-l2a` Earth Search с исходной обработкой (baseline до 04.00), каждая сцена проверена на совмещение: корреляция деталей при целых сдвигах ±1 пиксель, сцена принимается при нулевом лучшем сдвиге и корреляции от 0,97. Принято 59 сцен и 1 276 патчей, медианная корреляция 0,998 (минимум 0,983). Без L2A остались 105 патчей: 4 сцены целиком и 1 патч сцены `18-9-20_16PCC`.
- Разбиение `common` — официальное разбиение MARIDA по сценам, ограниченное патчами с L2A, одно для всех моделей:

| Часть | Патчей | Сцен | Пикселей мусора | Размеченных пикселей |
|---|---|---|---|---|
| train | 637 | 34 | 1 297 | 356 790 |
| val | 327 | 12 | 1 068 | 213 080 |
| test | 312 | 13 | 299 | 180 209 |

Разбиение по патчам со сценой, тайлом, регионом, датой, официальной частью и частью `common` — `reports/splits/detector_marida.csv`.

### Классы и разметка

Положительный класс — 1 «Marine Debris». Отрицательные — остальные размеченные классы MARIDA: 2 плотный и 3 редкий саргассум, 4 природная органика, 5 суда, 6 облака, 7 морская вода, 8 вода со взвесью, 9 пена, 10 мутная вода, 11 мелководье, 12 волны, 13 тени облаков, 14 кильватерные следы, 15 смешанная вода. Класс 0 «не размечено» — не фон: в обучении и метриках он не участвует, P, R, F1 и IoU считаются по размеченным пикселям, как в протоколе MARIDA. Отдельно считаются срабатывания на неразмеченной воде дальше 5 пикселей от размеченного мусора. Используются все уровни уверенности (`max_confidence_code = 3`).

## Концентрация (T3)

### Формула и контрольный пример

C = N / A, где N — число предметов, A — обследованная площадь, км². Пример: 12 предметов на 0,20 км² — C = 12 / 0,20 = 60 шт./км². Если модель дала 75 шт./км², абсолютная ошибка |75 − 60| = 15 шт./км²; MAE и RMSE считаются по таким ошибкам на событиях.

### Постановка проверки

- Профили не смешиваются, основная величина — `plastic-visual` (S2).
- Признаки (4 группы): координаты в км от центра профиля; сезон (синус и косинус дня года); география — расстояние до берега (Natural Earth 1:10m), речной вынос (Lebreton et al., 2017: взвешенный, сумма в радиусе 500 км, расстояние до ближайшей реки); погода — ветер ERA5 на момент учёта, среднее за 24 и 72 ч и максимум за 72 ч, высота волн ERA5-Ocean на момент учёта и за 24 ч (Open-Meteo). Наборы признаков: `spatial`, `spatial_season`, `spatial_geography`, `spatial_weather`, `all`, `weather_only`. Поля с ответом и протокол съёмки блокируются кодом; источник каждого признака записан в отчёт.
- Модели: медиана, среднее, ближайший сосед, IDW, Ridge, GLM Tweedie и сплайны, гауссов процесс, Random Forest, ExtraTrees, LightGBM, CatBoost, ансамбль.

Связь «снимок → концентрация» проверена на 7 парах того же дня в Чёрном море (раздел T1; `python -m littora_ml concentration satellite`, `reports/metrics/concentration/satellite_pairs.json`). Признаки считаются по пикселям воды в следе 6 км:

|---|---|---|
| FDI, среднее | −0,43 | 0,34 |
| FDI, 99-й процентиль | −0,18 | 0,70 |
| NDVI, среднее | −0,14 | 0,76 |

## Инференс и производительность

### Где тратится время

Анализ района выполняется в фоновом потоке (одновременно не больше двух анализов). Каждый результат содержит блок `timings`:

| Поле | Что измеряет |
|---|---|
| `quality_and_image_s` | доли классов SCL в районе, RGB и маска качества (до 1 600 пикселей по стороне) |
| `read_s` | чтение 12 COG-окон из Earth Search: 11 каналов и SCL, 20 и 60 м приводятся к 10 м |
| `inference_s` | сеть ONNX по скользящим окнам |
| `stability_s` | проверка устойчивости зон к поворотам |
| `zones_s` | связные области, признаки судна, доля покрытия |
| `structures_s` | запрос сооружений OpenStreetMap (кэшируется) |
| `layers_s` | PNG-слои и файл значений пикселей |
| `total_s`, `tiles`, `pixels` | всего, число окон сети, число пикселей района |

Числа:

- Сеть: ONNX RA-U-Net, вход 11 каналов, окна 256×256 с шагом 192, CPU (`CPUExecutionProvider`, 4 потока) — ≈0,08 с на окно. Время сети растёт с числом окон: на стороне L пикселей окон ⌈(L − 256) / 192⌉ + 1.
- Район предельного размера 34×34 км (12 млн пикселей) — 18 × 18 = 324 окна, ≈26 с только на сеть.
- Пример Новороссийска (≈11×9 км, 1 016 315 пикселей, 30 окон сети), замер `timings` из результата анализа в Docker на ноутбуке с Apple M-серии, пока на той же машине шло обучение сети (поэтому медленнее обычного):

| Этап | Время, с | Доля |
|---|---|---|
| RGB, маска качества и доли SCL (`quality_and_image_s`) | 19,9 | 20 % |
| чтение 11 каналов и SCL из облака (`read_s`) | 40,0 | 41 % |
| сеть, 30 окон (`inference_s`) | 13,1 | 13 % |
| проверка устойчивости к поворотам (`stability_s`) | 14,6 | 15 % |
| зоны, признаки, доля покрытия (`zones_s`) | 1,1 | 1 % |
| PNG-слои и значения пикселей (`layers_s`) | 3,9 | 4 % |
| сооружения OpenStreetMap (`structures_s`) | 3,7 | 4 % |
| всего (`total_s`) | 97,9 | |

  Больше всего времени уходит на чтение снимка по сети (≈60 % вместе с маской и RGB), сама сеть — около восьмой части. На свободной машине тот же район считается за ≈37 с. Маленький район (5×5 км) — единицы окон и десятки секунд, почти всё — чтение; большой (34×34 км) — сотни окон, и время сети становится сопоставимо с чтением.
- Проверка устойчивости: до 24 окон × 7 дополнительных ориентаций (8 видов с исходным), до ≈15 с.
- Исследовательская оценка на MARIDA использует TTA по 8 ориентациям (в 8 раз дороже); сервис делает один прогон на окно. Режим сервиса (без TTA, с маской моря) на test даёт F1 0,910, исследовательский режим с TTA и зонами от 2 пикселей — 0,902.
- Повторный запрос возвращается сразу: идентификатор анализа — первые 16 знаков SHA-256 от района (округление 10⁻⁵°), даты, окна поиска, выбранной сцены, цели, версии конвейера и отпечатков моделей детектора и концентрации. Готовый `result.json` читается с диска без расчёта. После выгрузки новой модели старый результат помечается `stale: true` и считается заново при следующем запросе. Поиск сцен кэшируется в памяти на 10 мин, ответы Open-Meteo и Overpass — в `storage/forcing` и `storage/osm`.

### Как ускорить

- Уменьшить район: время сети пропорционально числу окон, чтение — площади.
- Задать `scene_id`, если снимок уже выбран: пропускается поиск по каталогу.
- Повторять тот же запрос: результат берётся из сохранённого.
- GPU: сервис по умолчанию использует `CPUExecutionProvider` (`backend/app/analysis/detector.py`); для GPU нужны `onnxruntime-gpu` и провайдер `CUDAExecutionProvider` — в поставке это не настроено.
- Без файла `models/detector/service/stability.json` проверка устойчивости не выполняется (флаг «неустойчива к поворотам» пропадает, отпечаток модели меняется).

Значения пикселя (`/pixel`) сохраняются для районов до 4 млн пикселей (≈20×20 км).

## Дрейф, динамика, обследование, проверка командой (O6)

### Сценарий дрейфа

- `POST /api/v1/analyses/{id}/drift` считает сценарий для зон анализа (до 25 зон с наибольшей вероятностью), `GET` отдаёт сохранённый. Модель `littora-drift-2`; результат лежит рядом с анализом (`drift.json`), ответы Open-Meteo кэшируются.
- Скорость частицы: u = u_теч + s·u_Стокс + α·U10, где u_теч — течение SMOC за вычетом оценки стоксова дрейфа, u_Стокс — стоксов дрейф по высоте и периоду волн MFWAM, α — парусность, U10 — ветер на 10 м. Горизонтальная диффузия 5 м²/с, шаг RK2 15 мин, выход каждый час.
- Форсинг — Open-Meteo без ключей: течения SMOC и волны MFWAM 1/12° (Marine API), ветер ERA5 (Archive API) для дат старше 7 суток, иначе прогноз (Forecast API). Область — рамка зон плюс 50 км.
- Ансамбль: парусность 0,5, 1, 2 и 3 % × стоксов дрейф вкл./выкл. × 40 частиц = 320 частиц на зону; горизонты 6, 12, 24, 48 и 72 ч вперёд и до 48 ч назад.
- Суша — по SCL снимка анализа, без маски снимка — по сетке Open-Meteo. Частица, шагнувшая на сушу, остаётся в последней точке на воде; точки выброса ближе 2 км объединяются в участок побережья. Вероятности выноса даются с интервалом Уилсона 90 % только по разбросу ансамбля.
- Возможные источники — доля обратных траекторий, вошедших в район порта или устья реки из `data/aoi/russia.geojson`.
- Облако 90 % строится отдельным прогоном: к скорости частиц добавлено случайное блуждание Орнштейна — Уленбека σ = 0,2 м/с с памятью 48 ч (эффективная диффузия ≈6 900 м²/с), область форсинга для него расширена до ±100 км, доля облака за её пределами отмечается. Медианная траектория, выброс на берег, источники и обратный прогон считаются по основному ансамблю — его медианная траектория и сверялась с треками.

Калибровка облака (`reports/metrics/drift/spread.json`): настройка выбрана только на окнах подбора 2022–2023, проверка 2024 и Чёрное море посчитаны один раз.

| Выборка | Окон | В облаке 90 % через 24/48/72 ч, до калибровки | После калибровки |
|---|---|---|---|
| подбор: NAUTILOS 2022–2023 | 159 | 6 / 4 / 2 % | 94 / 90 / 90 % |
| проверка: NAUTILOS 2024 | 79 | 9 / 10 / 12 % | 100 / 100 / 100 % |
| Чёрное море: SVP-B 4401656, свободный дрейф 2026 | 66 | 8 / 6 / 3 % | 94 / 87 / 90 % |

Контур 50 % после калибровки не откалиброван (подбор 48/42/20 %, проверка 96/98/98 %) и в интерфейсе не показывается.

Сверка с треками (`reports/metrics/drift/drifters.json`), медиана расстояния от медианной траектории до реальной точки:

| Выборка | Горизонт | Окон | Сценарий, км | Неподвижная точка, км | Продолжение движения, км |
|---|---|---|---|---|---|
| 14 предметов мусора NAUTILOS, 6 миссий | 24 ч | 238 | 13,0 [8,4; 17,6] | 15,9 | 15,5 |
| то же | 72 ч | 99 | 24,0 [15,2; 50,5] | 23,8 | 46,0 |
| дрифтер SVP-B в Чёрном море | 72 ч | 59 | 24,8 | 41,4 | 24,7 |

Сценарий значимо не лучше ни неподвижной точки, ни продолжения прежнего движения (ДИ бутстрэпа по миссиям содержит 0); у одного черноморского дрифтера интервала нет. Окна дрифтеров Средиземного моря (400) и SWOT-Med (3 820) поставлены в очередь, но не посчитаны: им нужно до 101 939 вызовов Open-Meteo при бесплатной квоте 10 000 точек в сутки. Лучшая по трекам парусность по типам предметов (доски 0 % со Стоксом, бутылки 4 % со Стоксом, кольца 1,5 % без Стокса) — описание, а не проверенная настройка.

Статусы: «сценарий дрейфа» — проверенным прогнозом не является; «нет зон для дрейфа» — в анализе нет зон; «недостаточно данных» — у анализа нет снимка или нет данных Open-Meteo (такой результат не кэшируется).

### Динамика

- `GET /api/v1/timeline` — пролёты Sentinel-2 над районом (до 120 сут) и уже посчитанные анализы; `POST /api/v1/timeline/runs` — фоновый прогон детектора по пролётам (по умолчанию 6, до 12 или список `scene_ids`).
- Ряд — число и площадь зон выше порога на каждом снимке; это не динамика концентрации.
- `GET /api/v1/timeline/compare?before=&after=` сравнивает два анализа по перекрытию контуров с допуском 20 м: новые, сохранившиеся, исчезнувшие и ненаблюдавшиеся зоны с площадями. Зона без пары, место которой на другой дате закрыто облаками, тенью, без данных или вне снимка (открытой воды по SCL меньше 50 %), считается ненаблюдавшейся, а не исчезнувшей. Мусор дрейфует, поэтому «на том же месте» не обязательно тот же объект.

### План обследования

`POST /api/v1/analyses/{id}/survey`, модель `littora-survey-2`, статус «план обследования — расчётный»:

- зоны группируются в радиусе 0,5 км; ранг цели — взвешенная сумма: уверенность детектора 0,3, площадь 0,2, риск по дрейфу 0,2 (max вероятности выноса на берег и срочности ухода на 2 км за 24 ч), доступность 0,2 (время перехода от порта за 4 ч), польза проверки 0,1 (1 − |2p − 1|);
- маршрут судна от ближайшего порта из `data/aoi/ports.geojson` (до 250 км): ближайший сосед, затем 2-opt; расстояния по прямой без обхода берега; вылеты БПЛА по дальности `uav_range_km`;
- окно выхода — светлое время в ближайшие 3 сут, срочность — из сценария дрейфа, если он посчитан; ближайшие пролёты Sentinel-2 после снимка (до 8 за 10 сут);
- параметры по умолчанию: скорость 10 уз, дальность БПЛА 15 км, 5 целей на маршрут (до 12), 20 мин на цель, запас 3 ч; выгрузка маршрута в GPX.

### Проверка зон командой

- В досье зоны отмечается, что это на самом деле: вероятно мусор, судно, сооружение, след судна, пена, плёнка, шлейф или цветение, берег, край облака, чистая вода, не видно — с уверенностью 1–3. Отметки копятся в `storage/reviews`, выгружаются в CSV и GeoJSON (`/api/v1/reviews/export.*`) и загружаются для дообучения как трудные примеры (`littora_ml.detector.review_labels`).
- Первая партия — аудит команды 200 зон на 7 сценах мая — сентября 2025 г. у российского берега Чёрного и Азовского морей (`data/validation/black_sea_zone_audit.csv`; Керченский пролив 81, Таганрогский залив 43, Новороссийск 20, Анапа 19, Темрюкский залив 19, Сочи 14, Туапсе 4; по 100 мелких зон 2–3 пикс. и крупных от 4 пикс.). Итог: чистая вода 45, не видно 40, шлейфы и цветение 39, суда 30, берег 24, края облаков 12, сооружения 5, пена 3, плёнка 1, мусор 1.
- Из аудита для кандидата на дообучение взяты уверенные (2–3) и различимые на снимке классы: 115 зон (шлейфы 39, суда 30, берег 24, края облаков 12, сооружения 5, пена 3, плёнка 1, мусор 1) в 53 окнах 256×256 из C1, 1 035 размеченных пикселей (`python -m littora_ml detector prepare --variant review`). «Не видно» и «чистая вода» не берутся — сеть может видеть то, чего не видит человек. Сервисная модель на этих окнах не обучалась. Сцены аудита не пересекаются со сценами проверки на заведомом фоне Чёрного моря.

## Веб-карта: экраны и функции

Карта одна на всё приложение; режимы переключаются клавишами `1`–`5`.

| Режим | Клавиша | Что показывает |
|---|---|---|
| Мониторинг | `1` | каталог снимков района с пригодностью, запуск анализа, снимок и маска качества, вероятность и зоны, полевые измерения, таблица объектов и досье зоны, история запросов, выгрузка |
| Динамика | `2` | пролёты Sentinel-2 по району, прогон до 12 пролётов, детекции по датам, сравнение двух дат шторкой, прозрачностью или линзой |
| Прогноз | `3` | сценарий дрейфа зон текущего анализа: облако 90 %, медианная траектория, обратный дрейф, частицы течений, риск выноса на берег |
| Обследование | `4` | цели, срочность, маршрут от порта, радиус поиска, окно выхода, выгрузка GPX |
| Модели | `5` | «Как читать отчёт» (чему доверять, что перепроверять, чего не выводить), галерея «вблизи и издалека» (мишени PLP, удачные и ложные обнаружения, пары судно — спутник), данные кейса S1–S4 с причинами отсутствия пар, сравнение моделей на одном test, порог и ошибки, проверки вне обучения, коллекция C1, флаги зон, концентрация, пары судно — спутник, дрейф; данные — `/api/v1/models`, печатная версия — `/api/v1/models/report.html` |

Слои:

| Группа | Слои |
|---|---|
| Снимок даты | RGB; ложные цвета B08-B04-B03; FDI; NDVI; контур сцены |
| Анализ района | район анализа и статус; облака, блики, нет данных (маска качества по SCL) |
| Результаты модели | вероятность мусора (калиброванная, прозрачна ниже четверти порога); зоны детектора; доля покрытия пикселя |
| Контекст | полевые измерения, шт./км²; разметка команды в Чёрном море — 45 полигонов заведомого фона (суда, садки, пятна, шлейфы, облака, вода) и 200 точек аудита зон детектора с классом и уверенностью (`data/validation`); граница района; сетка и рамка; подписи |
| Прогноз, обследование | облако 90 %, медиана траектории, обратный дрейф, частицы, берег; цели, маршрут, радиус поиска |

Доля покрытия пикселя — линейное смешение в B08 между фоном воды (среднее по морю в окне 21×21 пикселей) и отражением пластика 0,15 (диапазон 0,08–0,30 даёт интервал); площадь покрытия зоны — сумма долей × 100 м². Это физическая оценка, на данных она не проверена.

Досье зоны:

1. Сводка — рекомендация «что делать» (проверить на месте; перепроверить на следующем снимке; вероятно не мусор — по флагам, устойчивости и вероятности), максимальная калиброванная вероятность, площадь, доля покрытия пикселя, флаги с доказательствами, центр зоны, детектор, устойчивость к поворотам.
2. Сопоставление с измерениями с судна — 5 ближайших измерений кейса; сопоставимыми считаются не дальше 50 км и не больше 3 сут от снимка.
3. Снимок — фрагмент вокруг зоны.
4. Условия съёмки — время, спутник и тайл, облачность тайла, высота Солнца, маска SCL в зоне, ветер и волны Open-Meteo на момент снимка.
5. Проверка командой — отметка и итог по зоне.
6. Дальше — расчёт дрейфа.

На карте зоны отрисованы по рекомендации: закрашенный маркер — проверить на месте, бледный — перепроверить, полый серый контур — похоже на судно или сооружение. Слой «Где доступна концентрация» (зелёный пунктир) показывает области применимости полевых профилей: концентрация выдаётся только внутри них и в сезонное окно.

Панель анализа: блок «Коротко» — итог одной-двумя фразами и предупреждение, если ветер на момент снимка 8 м/с и сильнее (пена и барашки дают ложные зоны); быстрые переключатели слоёв (RGB, ложные цвета, FDI, NDVI, маска, вероятность, покрытие, зоны); сравнение всех целевых величин для этого района и даты; технические поля и время расчёта — под «Подробности для специалиста»; кнопки «Сценарий дрейфа» и «Маршрут обследования из порта» — переход в «Прогноз» и «Обследование» с этим анализом. Дополнительный фильтр «Плотность материала, м²/км²» (по умолчанию выключен): сумма площади материала зон в ячейке 1 км без зон «похоже на судно или сооружение», классы до 15, 15–40, 40–100 и больше 100 м²/км²; это оценка по доле покрытия, не концентрация. Подсказка сверху карты есть во всех режимах с картой и в «Мониторинге» меняется по ходу работы: что сделать дальше при пустом, непригодном, пустом по зонам и готовом анализе и в карточке зоны.

Инструменты карты: масштабная линейка; сетка и рамка (`G`); лупа — значения пикселя под курсором (`I`: вероятность и порог, FDI, NDVI, доля покрытия, класс SCL, отражение B02, B03, B04, B08, B11, зона); линейка — расстояния (`R`); переход по объектам в порядке приоритета (`J`, `K`); показать район целиком (`F`); север вверх (`N`); тема (`T`).

Статусы результата:

| Где | Статус | Когда |
|---|---|---|
| анализ и детекция | обнаружено | модель нашла зоны на пригодном снимке |
| анализ и детекция | не обнаружено | снимок пригоден, зон нет (зона — от 2 связных пикселей выше порога) |
| анализ и детекция | недостаточно данных | нет снимка в окне поиска; снимок непригоден (облака и тени больше 30 %, пропусков больше 20 %, воды меньше 5 %) или не читается; детектор не подключён |
| концентрация | исследовательская оценка | медиана профиля с интервалом; перенос на снимки не подтверждён |
| концентрация | концентрация недоступна | район или дата вне области и сезона профиля, нет снимка или нет модели для цели |
| дрейф | сценарий дрейфа | траектории ансамбля по течениям, ветру и волнам; сверка с треками есть, но точнее простых схем сценарий не оказался, поэтому это не прогноз |
| дрейф | нет зон для дрейфа | в анализе нет зон детекции |
| дрейф | недостаточно данных | у анализа нет снимка или нет данных Open-Meteo |
| обследование | план обследования — расчётный | маршрут судна и вылеты БПЛА по зонам; срочность из сценария дрейфа, если он посчитан |
| обследование | нет зон для обследования | в анализе нет зон детекции |
| обследование | недостаточно данных | у анализа нет снимка |

Запрос на район больше 1° по стороне или больше предела детектора (12 млн пикселей) отклоняется с сообщением до расчёта.

Выгрузка:

| Что | Формат | Откуда |
|---|---|---|
| анализ: район со статусом и концентрацией, зоны, полевые измерения | GeoJSON, CSV (столбцы `feature`, `id`, `value_kind`, `status`, `value`, `unit`, `lower`, `upper`, `target`, `measurement_profile`, `date`, `scene_id`, `longitude`, `latitude`, `note`) | панель анализа, `/api/v1/analyses/{id}/export.*` |

Демо-режим: клавиша `D` включает фикстуры на участке «Гондурасский залив»; они помечены «ДЕМО» и по умолчанию выключены (`NEXT_PUBLIC_DEMO_FIXTURES=false`). Плановые пролёты и очередь событий детекции работают только на демо-данных.

## Воспроизводимость (T4)

### Окружение

Окружение ML ставится из зафиксированных версий `ml/requirements.lock` (80 пакетов, среди них numpy 2.5.3, pandas 3.0.6, scikit-learn 1.9.1, lightgbm 4.7.0, catboost 1.2.10, torch 2.14.0, segmentation_models_pytorch 0.5.0, onnx 1.23.0, onnxruntime 1.30.0, rasterio 1.5.1, shapely 2.1.2); пакеты `backend` и `ml` ставятся в тот же venv. Артефакты в репозитории получены на Python 3.12. Версии сервиса: backend — `backend/pyproject.toml` (FastAPI ≥ 0.141, pydantic 2, onnxruntime ≥ 1.20, rasterio, shapely, scipy), frontend — `frontend/package.json` и `package-lock.json` (Next.js 16.3.6, React 19, MapLibre GL 6, deck.gl 9.4, TanStack Query 5, Zustand 5, Tailwind CSS 4, TypeScript 5).

```bash
make ml-env
```


Нужен интернет: снимки из Earth Search, погода для признаков концентрации и течения для дрейфа из Open-Meteo.

Каждый файл метрик детектора содержит val и test, порог и его источник, ложные срабатывания по классам MARIDA и по сценам, SHA-256 конфига; у прогонов на общем разбиении ещё SHA-256 кода, постобработку, 95 % ДИ по сценам и срабатывания на неразмеченной воде; у сетей — устройство, число параметров, история обучения и решение по TTA. Сводка — `reports/metrics/detector/summary.csv` и `summary.json`.

### Разбиения и защита от утечек

- `reports/splits/detector_marida.csv` — 1 381 патч: имя, сцена, тайл, регион, дата, официальная часть, наличие L2A, часть `common`, пиксели мусора и размеченные пиксели. Разбиение по сценам, одно для всех моделей; всё, что подбирается, подбирается на val; test считается один раз; внешние проверки — с замороженным порогом.
- `reports/splits/concentration.csv` — 4 400 строк: `sample_id`, `event_id`, профиль, дата, отчёт, повтор, группа дня съёмки, внешний фолд, пространственный блок (220 событий × 10 повторов × 2 отчёта). Все записи одного дня съёмки всегда в одном фолде; выбор модели вложенный.
- Поля с ответом и протокол съёмки запрещены как признаки кодом; роли всех 56 столбцов с доказательствами — в `reports/audit/case_audit.json` (`leakage`).
- Дрейф: подбор 2022–2023, проверка 2024 и черноморский дрифтер посчитаны один раз.
- Детектор не обучался на сценах DOORS, по которым проверялась связь «снимок → концентрация»; сцены аудита команды не пересекаются со сценами заведомого фона.


```
backend/      FastAPI, rasterio, shapely, scipy, onnxruntime, pytest, ruff; config/case.toml

configs/      конфиги детектора, концентрации и сверки дрейфа

data/         данные; в git каталог источников, районы, манифесты, CSV кейса и разметка проверки
reports/      реестр пар, аудит, метрики, предсказания, разбиения, рисунки
scripts/data/ загрузка и подготовка внешних данных
Makefile      окружение ML и все шаги обучения и оценки
compose.yaml  frontend и backend в контейнерах
```

Backend (`backend/app`):

- `case` — данные кейса: конфигурация цели, отбор записей, проверка N/A, геометрия следов, положение Солнца, подбор пар, реестр, CLI `python -m app.case`.
- `earth` — каталог STAC и чтение COG: каналы для детектора, доли классов SCL, RGB и маска качества в PNG.
- `analysis` — запрос анализа, статусы, детектор ONNX с калибровкой, маска моря и зоны, признаки судов, устойчивость зон, композиты и доля покрытия, значения пикселя, сооружения OpenStreetMap и порты, условия съёмки, полевые модели концентрации, сохранение и выгрузка.
- `drift` — форсинг Open-Meteo, ансамбль частиц, маска суши, огибающие с калиброванным разбросом, выброс на берег и источники.
- `survey` — план обследования: группы зон, ранг целей, маршрут судна, вылеты БПЛА, срочность по дрейфу.
- `timeline` — пролёты над районом, фоновые прогоны детектора и сравнение пролётов.
- `review` — отметки команды по зонам, аудит, итог, выгрузка.
- `evaluation` — отчёт `/api/v1/models` из `reports/` и `models/`; файлы перечитываются только при изменении времени или размера, повреждённый файл прогона пропускается.
- `api`, `schemas`, `core` — маршруты, схемы ответов, настройки, реестр возможностей, ошибки, логирование и идентификатор запроса. Приложение собирается в `create_app()`.

ML (`ml/littora_ml`, CLI `python -m littora_ml`):

- `audit` — аудит CSV кейса и проверка утечек;
- `detector` — кэши MARIDA, L2A и C1, бейзлайны, сети, ансамбли, постобработка, калибровка, правило судов, устойчивость зон, метрики, выгрузка ONNX, проверки по регионам, в Чёрном море, на PLP и на C1, загрузка отметок команды;
- `concentration` — признаки, вложенная проверка, модели, внешняя проверка на данных Чёрного моря, выгрузка в сервис;
- `satellite` — связь снимка и концентрации на парах S4;
- `drift_check` — сверка сценария дрейфа с треками и подбор разброса огибающей;
- `common` — конфиги, пути, сиды; `splits_export.py` — разбиения в `reports/splits`.

Frontend (`frontend/src`):

- Карта одна на всё приложение; её не пересоздают ни при смене режима, ни при входе с экрана входа.
- Режимы — страницы Next.js; каждая добавляет свои панели в общую оболочку и свои слои deck.gl на карту.
- Данные — только через хуки `src/data/*`, каждый ответ помечен источником; демо-данные лежат отдельно в `src/demo`.
- Недоступная возможность из `/api/v1/meta` показывается как «не подключено»; когда статус меняется на `available`, интерфейс подключает её сам.

## Дополнительные исследования команды

Отдельные исследовательские прогоны команды. В сервис они не подключены и на метрики выше не влияют; ниже — что сделано, на каких данных и что получилось.

**EDA данных кейса** (`notebooks/01_macroplastic_eda.ipynb`, `reports/eda/`, окружение — `ml/eda/`). Независимый аудит CSV и спутниковых пар, проверка отбора и N/A, пропуски, география, групповые разбиения и три базовых прогноза концентрации по каждому профилю отдельно. Совпадает с программным аудитом (`reports/audit/`) по составу событий и профилей.

**EDA MARIDA и первые детекторы** (`notebooks/02_marida_eda.ipynb`, `reports/marida/`, `ml/marida/`). Проверены все 1 381 изображение и маски; разбиение с учётом соседних сцен; спектральный Random Forest и пороговое правило на исходной обработке MARIDA — отправная точка для сетей и LightGBM этого README.

**Расширение данных детектора** (`notebooks/03_data_expansion.ipynb`, `reports/expansion/`, `ml/expansion/`). MADOS — 2 803 кропа, 1,48 млн размеченных пикселей: совместный Random Forest MARIDA + MADOS поднял F1 с 0,446 до 0,567 на MADOS и с 0,641 до 0,701 на тестовой части MARIDA этого прогона (повторный инференс 642 168 пикселей совпал с сохранёнными оценками до 1e-12). Независимость источников по месту и времени не доказана: у MADOS нет геопривязки кропов, поэтому в сервис не переносилось. PLP 2019: 65 размеченных пикселей, регрессия доли покрытия не лучше среднего train. ERA5: погода предыдущего дня для 74 визуальных событий не улучшила MAE концентрации.

**Обучение на целевом продукте L2A (Random Forest).** Для 35 из 63 сцен MARIDA найден тот же продукт L2A; 190 патчей (train 110, val 38, test 42 — 102 пикселя мусора). Random Forest, обученный на L2A, на тех же пикселях test дал F1 0,739 против 0,323 у модели, обученной на исходной обработке MARIDA (прирост +0,42, 95 % ДИ по группам 0,24–0,54); контроль на тех же пикселях в исходной обработке с порогом по L2A val — 0,641. Вывод совпадает с проверкой сдвига домена в разделе «Детектор»: учиться нужно на продукте, который читает сервис. В географически удалённой группе test (Филиппины, более 1 300 км до train) модель пропустила все 10 пикселей мусора — перенос в новые регионы остаётся главным ограничением.

**Погода, волны и течения как признаки детектора.** 1 524 ответа ERA5, ERA5-Ocean, HYCOM и SMOC; обогащены 318 полевых событий и 190 патчей. Спектральный Random Forest: F1 0,739; с полным набором условий среды — 0,022 (разница −0,717, 95 % ДИ −0,836…−0,069): ложных срабатываний 4 184 вместо 9, в основном на мутной воде и воде со взвесью. Условия среды забрали 78,6 % важности — модель запоминает место и дату, а не спектр мусора. Поэтому в сервисе погода не входит в детектор, а показывается рядом со снимком и предупреждает о сильном ветре.

**Бургас в модели концентрации.** SEANOE DOI 10.17882/98351 (IBER-BAS, проект BRIDGE-BS): 84 учёта 2021–2023, 8 повторяемых трансектов, полоса 2 250 × 6 м (0,0135 км²), 26 настоящих нулей. Добавление Бургаса в обучение на тех же 33 событиях DOORS и тех же группах изменило MAE с 182,8 до 181,5 шт./км² (разница +1,4, 95 % ДИ −3,9…+7,5) — не значимо. Перенос во времени (2021–2022 → 2023): медиана train 727, модель по месту и сезону 695 шт./км²; средняя плотность выросла со 120 в 2022 до 791 шт./км² в 2023 — межгодовой сдвиг сильнее, чем то, что объясняют место и сезон. Вывод тот же, что во внешней проверке раздела «Концентрация»: сервис выдаёт медиану профиля с интервалом.

**Мост к независимой проверке в Чёрном море.** Исходные данные DOORS: 27 спектров TriOS (451 канал, 400–850 нм) с UTC и координатами, свойства воды (TSM 0,4–26,5 мг/л, хлорофилл медиана 0,27 мг/м³, Secchi медиана 4 м), 12 кропов Sentinel-2 Чёрного моря (786 432 пикселя) со статистикой каналов и SCL. Подтверждённой разметки мусора и фона на них пока нет — это задел для будущей независимой проверки; новых заявлений о качестве не делается.

**RA-U-Net + XGBoost на исходной обработке MARIDA.** Сеть с Dice-лоссом или OHEM и градиентный бустинг поверх, веса ансамбля и порог выбраны по val, официальное разбиение MARIDA: test F1 0,876 и 0,861, IoU 0,780 и 0,756, AP 0,914 и 0,905. На том же разбиении наши RA-U-Net и LightGBM — 0,857 и 0,868. В сервис не переносилось: сервис работает на L2A, где этот ансамбль не проверялся, а выигрыш над одной сетью меньше разброса между сценами.

## Ограничения и развитие

Ограничения:

- Количественная модель — главное узкое место: полевых событий мало (33–83 на профиль, 12–26 дней съёмки), синхронных пар со снимками всего 7 и только для «всего мусора» в Чёрном море, связи признаков снимка с концентрацией на них нет. Поэтому концентрация — медиана профиля с интервалом, только в области и сезоне полевых данных; для морей России вне района DOORS ответ «концентрация недоступна».
- Детектор не видит объекты мельче ≈10 м; у российского берега его зоны по аудиту команды — в основном вода, шлейфы и цветение, суда и берег, мусором признана 1 зона из 200. Флаги помогают, но не заменяют проверку.
- Сервис читает `sentinel-2-c1-l2a`, а сеть обучена на MARIDA и `sentinel-2-l2a`; на части дат между коллекциями есть субпиксельный сдвиг (проверка на C1 разницы качества не показала).
- Доля покрытия пикселя — модель смешения без проверки на данных.
- Сценарий дрейфа сверен с малым числом треков (14 предметов, 1 дрифтер) и значимо не лучше простых эталонов; 4 220 окон дрифтеров не посчитаны из-за квоты Open-Meteo. Выгрузка сценария дрейфа в GeoJSON в интерфейсе не подключена.
- План обследования считает расстояния по прямой, без обхода берега, погоды и допусков судна.
- Сервис зависит от доступности Earth Search, Open-Meteo и Overpass; при отказе каталога анализ отвечает 502, без Overpass зоны остаются без флага сооружения.

Дальше:

2. Дообучение детектора на Collection-1 с совмещением разметки и трудными примерами из проверки зон командой (шлейфы, цветение, суда); замена сервисной модели только по правилу `c1check`.
3. Сверка дрейфа на дрифтерах Средиземного моря и SWOT-Med по мере квоты Open-Meteo; статистика по типам дрифтеров.
4. Проверка доли покрытия пикселя на мишенях PLP 2022–2023 с известной долей.
